# 商城后端

源码路径以同级的 `商城管理系统/` 为根目录。日常启动与关闭见 [项目运行说明](../商城管理系统/README.md)。

Java 17 及以上、Spring Boot 3.5.16、Spring Security、JdbcTemplate。默认使用 H2 文件数据库，安装 Java 和 Maven 后即可独立运行；另提供 MySQL 8 配置。

## 启动

在本目录运行：

```powershell
mvn spring-boot:run
```

或先构建再运行：

```powershell
mvn clean package
java -jar target/mall-backend-1.0.0.jar
```

服务地址为 `http://127.0.0.1:8081`，健康检查为 `GET /api/health`。页面由旁边的 `frontend-vue3` 工程提供，开发时 Vite 将 `/api` 转发到该服务。

初始管理员 `admin / Admin@123456`，员工 `staff / Staff@123456`。首次运行创建账号、分类、示例商品，之后根据数据库中的 `bootstrap_v1` 标记跳过初始化，不会覆盖已有商品、密码、库存或订单。

## 数据库

默认数据文件写入启动工作目录的 `data/mall.mv.db`，从本目录启动即可固定在 `backend/data`。重新启动读取同一个文件，浏览器刷新不会丢数据。`schema.sql` 仅使用 `CREATE TABLE IF NOT EXISTS`，没有清空表语句。

MySQL 模式必须提供独立数据库的连接信息：

```powershell
$env:MALL_DB_URL = 'jdbc:mysql://127.0.0.1:3307/mall_admin?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai'
$env:MALL_DB_USER = '你自己创建的数据库账号'
$env:MALL_DB_PASSWORD = '该账号的密码'
java -jar target/mall-backend-1.0.0.jar --spring.profiles.active=mysql
```

先在你自己的 MySQL 实例里创建名为 `mall_admin` 的新数据库。应用只在指定库内建表；不要填写原若依项目的数据库。具体本机一键启动方式见项目根目录的启动脚本和文档。

## 代码分层

- `controller`：接收 HTTP 请求、触发参数校验、返回 JSON。
- `model`：请求与响应结构；金额使用 `BigDecimal`。
- `service`：业务规则、权限以外的约束与事务边界。
- `repository`：显式参数化 SQL，负责真实数据读写。
- `config`：会话认证、CSRF、密码加密、首次数据初始化。
- `common`：统一错误响应 `{ "message": "错误说明" }`。

## 认证与业务规则

登录前先 `GET /api/auth/csrf` 取得 `{token}`，所有写请求通过 `X-CSRF-TOKEN` 请求头携带令牌。`POST /api/auth/login` 使用表单编码的 `username` 和 `password`，成功返回当前用户并使用 `JSESSIONID` Cookie 保持会话。登录或退出会刷新/销毁令牌，因此前端会重新获取令牌。

`ADMIN` 能管理用户与所有业务，`STAFF` 只能管理分类、商品、订单和查看统计。密码使用 BCrypt 摘要保存；停用或改密码使已有会话在下一次请求时失效，角色变化也会刷新已有会话的权限。

订单创建时按照商品 ID 排序加行锁，使用服务器端价格计算金额并保存商品名称与单价快照。库存扣减、订单及明细写入在同一事务中完成。任意商品不足或下架时全部回滚。取消订单先锁定订单再按固定顺序锁商品，只能归还一次库存。

状态流转为 `PENDING → PAID → SHIPPED → COMPLETED`；仅 `PENDING` 和 `PAID` 可以变成 `CANCELLED`。销售额统计仅包含 `PAID`、`SHIPPED`、`COMPLETED`。

上下架使用独立的 `PUT /api/products/{id}/status`，只修改状态；完整编辑商品包含明确的库存设置。已被订单引用的商品不允许物理删除，可以下架；有商品的分类不允许删除。`DELETE /api/users/{id}` 表示停用而不是物理删除，当前登录账号和最后一个启用的管理员受保护。

## 验证

```powershell
mvn test
```

集成测试使用独立的 H2 内存数据库，实际执行 Spring Security 过滤器、Controller、Service 与 SQL。覆盖认证/CSRF/角色限制、参数与分页、订单价格快照和状态、事务回滚、取消归还、两个并发订单抢最后一件库存、账号变更使会话失效、种子重跑不覆盖数据。

如果在当前机器上通过项目自己的 Maven 缓存构建，命令为 `mvn '-Dmaven.repo.local=.m2/repository' test`；该缓存已加入忽略规则。
