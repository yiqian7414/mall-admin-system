# 我的商城管理系统 · Vue 3 前端

源码路径以同级的 `商城管理系统/` 为根目录。日常启动与关闭见 [项目运行说明](../商城管理系统/README.md)。

这是独立商城管理后台的正式前端，使用 **Vue 3 + JavaScript + Vue Router + Vite**。页面数据全部来自 Spring Boot 的真实 API，没有在前端假造商品、订单或账号数据。

## 已实现的功能

- 登录、刷新后恢复会话、退出、会话过期回到登录页。
- 工作台：商品/分类/订单统计、销售额、待付款统计、库存预警、最近订单。
- 分类：新增、编辑、删除；关联商品的分类由后台保护。
- 商品：新增、编辑、删除、搜索、分类/状态筛选、分页、库存调整、独立上下架操作。
- 订单：从在售商品创建多商品订单、数量检查、金额预览、搜索、分页、详情、付款/发货/完成/取消。
- 账号：管理员新增与编辑账号、分配角色、启用与停用；员工不能访问账号管理。
- 通用交互：响应式侧栏、表格、弹窗、页内通知、确认框、加载/错误/空状态。

付款是后台人工确认记录，未接入真实支付渠道。订单价格与金额由后台计算；前端预览不作为结算依据。创建订单扣库，取消订单归还库存。账号“停用”保留历史记录，可重新启用。

## 启动

需要符合 package.json engines 的 Node.js，后端默认监听 http://127.0.0.1:8081。

```powershell
cd "C:\Users\石慧达\Desktop\前后端分离\商城管理系统\frontend-vue3"
npm.cmd install
npm.cmd run dev -- --port 5174 --strictPort
```

打开 http://127.0.0.1:5174/。项目总目录的启动脚本会同时启动前后端，请优先参照总 README。依赖已安装时不必重复 install。

Vite 开发服务器把 /api 请求代理到 http://127.0.0.1:8081，因此浏览器只访问同一个前端来源，Session Cookie 不需要跨域配置。修改代理配置后需要重启 Vite。

## 构建

```powershell
npm.cmd run build
```

生成文件在 dist/。Vite preview 只用于预览静态构建，默认不包含开发服务器的 API 代理。实际部署需要 Web 服务把 /api 转发到后端，并把前端页面路径回退到 index.html。

## 请求与认证流程

1. 首次进入路由，通过 GET /api/auth/me 恢复用户身份。
2. 未登录进入 /login，登录提交 application/x-www-form-urlencoded 的用户名和密码。
3. POST/PUT/DELETE 前取得 GET /api/auth/csrf 返回的令牌，放进 X-CSRF-TOKEN 请求头。
4. 所有请求使用 credentials: include，让浏览器携带 Session Cookie。
5. 登录和退出会更换或清除 Session，前端丢弃旧令牌并重新获取。
6. HTTP 401 清除用户状态并回到登录页；403 与其他错误显示后台返回的 message。
7. 前端隐藏管理员专用导航并阻止对应路由，后台仍独立验证权限。

商品上下架调用 PUT /api/products/{id}/status，只传 status，避免把列表中的旧库存写回后台。普通商品编辑中填写库存属于显式库存调整。

## 学习路线

先阅读总项目的逐行讲解与 API 文档，再依次看：

1. main.js → App.vue → router.js：页面如何启动和切换。
2. api.js → session.js → LoginView.vue：浏览器如何登录并请求后台。
3. CategoriesView.vue：最短的完整 CRUD 流程。
4. ProductsView.vue：表单、分页、搜索、状态操作。
5. OrdersView.vue：复杂草稿、计算属性、库存与状态流程。
6. UsersView.vue：权限与账号管理。
7. components/：提取复用页面元素。

当前正式版数据持久化由后端和数据库负责，页面通过接口读取和保存数据。
